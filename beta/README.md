# 弹指足球 Beta

Beta 在独立目录运行。普通模式保留稳定版物理并关闭球员技能；乱斗模式开放 12 名球员的技能。所有技能只在实际比赛中抽取，电脑试算不会提前查看或重复抽取随机结果。

## 默认阵容

双方默认使用相同的五人阵容并镜像站位：范队、坎特、魔笛、眉西、AB罗。每队内部五人不重复，双方可以选择同一球员；玩家仍可从全部 12 人中自由更换。相同默认阵容避免了预设角色配置的差异，不代表先手、随机技能或所有自由组合已经达到严格平衡。

## 平衡验证

早期 Beta 0.1 以中档电脑进行了 24 场真实自战（早于本轮技能修正、纳瓦斯与新阵型），分为两组各 12 场；每个种子交换阵容所在左右两侧，先到 3 球获胜，每场最多 80 个正常回合。24 场均正常完成，无运动超时。

| 测试配置 | 阵容 A / B 胜场 | 总进球 | 平均正常回合 |
| --- | --- | --- | --- |
| 初始不对称阵容 | 10 / 2 | 52 | 30.83 |
| 对调坎特与贝林 | 11 / 1 | 41 | 23.25 |

这些样本显示原先两组默认阵容不宜被称为平衡，因此最终改为双方相同阵容，并未据少量样本盲目修改单项技能概率。测试中电脑主要追球，没有自然触发罚下或受伤；这些状态通过强制随机数和实际碰撞测试覆盖，不能用本组自战证明其长期影响。

在真实物理中，60% 力度的无碰撞滑行距离为：普通球员约 318.13 像素、坎特约 365.71 像素（1.150 倍）、受伤球员约 95.24 像素（0.299 倍）。苏牙限制为每名球员每场最多触发一次，每个对手碰撞配对每杆只抽取一次；伤势不叠加或刷新，范队每场开始只有1层护盾，消耗后本场不补充。进球重置站位不会复活罚下球员、消除伤势或补回护盾。

测试与手动自战命令：

```sh
node --test beta/tests/*.test.cjs
node beta/simulate-balance.cjs 6 beta/balance-current-report.json
node beta/simulate-balance.cjs 6 beta/balance-initial-report.json initial
node beta/simulate-balance.cjs 6 beta/balance-swapped-report.json swap-midfield
```

自战脚本独立运行，不加入日常测试。两份保留报告包含当时使用的阵容、逐场数据与最终默认选择说明。它们是有限样本的记录，不是胜率或概率的统计保证。


## 入口与玩法

- 在线 Beta：https://yiiiiming.github.io/Table-Football/beta/
- 正式版：https://yiiiiming.github.io/Table-Football/

菜单中的「经典模式」和「球员大乱斗」各自支持单人低／中／高 AI 与同屏双人。先选择玩法与单人／双人，再进入独立阵容页。左侧阵型图与编号位置牌标明前锋、后卫／门将；球员库另标明前锋、中场、后卫和门将职业，提供均衡双锋、稳守反击、两翼拉开三种预设；右侧球员列表独立滚动。可将球员拖到位置，或先点击位置再点击球员；同队已上场球员会交换位置。双队分别保存阵型，进球后按各自阵型重新摆放。每队不重复，两队可使用同一球员。比赛中可打开菜单，保留当前对局继续，或点击开始以新配置重新开局。

技能的完整条件与数值以 `roster.js` 和球员卡为准。金框表示眉西额外行动就绪；获得额外行动后只能使用该枚圆片。进球会取消额外行动。受伤、离场和已消耗护盾跨进球保留，重开比赛才恢复。

## 头像与创作记录

12张头像由内置 imagegen 生成，原图在 `assets/players/`，成功生成及编辑的精确提示词在 `assets/portrait-prompts.json`。按用户确认的相关肖像授权制作10张真人近似卡通；AB罗与眉西在生成工具限制后，按用户同意采用原创人物替代。昵称、技能和比赛事件属于虚构游戏设定，不表示真人行为或官方背书。授权由用户确认，本项目未独立审核授权范围。

头像保持原始PNG，首次加载素材约22MiB，后续可使用浏览器缓存。阵容与比分仅在当前页面内存保存，刷新页面会重置。已做模块及回合自动化测试与HTTP资源验证；本次未进行真实浏览器渲染验收。


## Beta 0.1.1 规则澄清

- AB罗的1:1指白球与本次碰到的**对方球员**质量相同，不是与AB罗相同；每次与不同对方球员接触时，在碰撞计算前匹配质量。本次出杆结束后恢复白球原质量。
- 苏牙是被动接触技能：自己撞人、被对方撞到、被第三名球员推着碰到对方，都可以判定。无需轮到苏牙或由苏牙主动出手。同一出杆对同一对手只判定一次，4%概率、每场一次及50%自身红牌代价保留。
- 眉西亮起金框时，这回合用他出手后，球停稳还能用他再出手一次；不能无限连动，进球后结束。
- 球员昵称统一为「哈蓝德」。

- 新增纳瓦斯「海底捞月」：每场两次被动救险，白球进入己方门前110单位、球门上下各扩30单位的危险区时，自动解围到己方四分之一场边线附近；落点有球员时寻找邻近空位，没有安全落点则不消耗次数。球心已经越过球门线不会被救回。次数跨进球保留，新比赛恢复。
- 普通模式与大乱斗（以及稳定版）采用42单位的小圆角，碰撞沿弧线反弹；两侧球门始终敞开，不设置首杆免进球或隐形挡板。
- 菜单分两步、球员库单独滚动；支持鼠标拖整行、触屏拖头像和点选换人。球员职业作选人参考，不限制摆入其他位置。


## 开球站位验证（0.1.1）

三套站位均采用三人后场防线，前场分别为双锋接应、双锋回收和边路展开。每个位置仍可自由选择球员职业。球门始终敞开，所有回合使用同样的计分和碰撞规则，没有首杆禁进球规则。

最终三套站位完成 **1,025,694 次**固定随机分支的开球模拟，未发现进球或乌龙。覆盖全部9种阵型配对、两个进攻方向及各个可用出杆位置：

| 扫描 | 样本数 | 首杆进球 |
| --- | ---: | ---: |
| 12类体型、移动属性与技能分支，含全方向及反弹目标 | 249,372 | 0 |
| 坎特、丁丁、落后贝林，0.25°角度步进及7种力度 | 290,682 | 0 |
| 对方哈蓝德／范队的20种位置排列 | 255,600 | 0 |
| 双方苏牙的被动位置与红牌结果分支 | 230,040 | 0 |

复现命令、参数及限制见 [formations-report.json](formations-report.json) 和 `simulate-formations.cjs`。这些是有限采样的回归证据，不是对任意连续角度、力度、全部阵容组合的数学保证；进球后仍有球员离场的摆阵也不在完整首发验证范围。眉西的额外出手属于第二次行动。已验证移开中路守门圆片后，对方第二杆可以正常进球。

仓库共113项自动检查通过，涵盖两入口物理、真实技能与回合、拖拽和分步菜单。浏览器画面未进行自动化渲染验收。
